# 10. SQL 기반 카드 포트폴리오 리스크 분석

## 프로젝트 개요
08-card-credit-risk에서 사용한 대만 카드사 데이터를 SQLite 데이터베이스로
구축하고, 리스크관리 실무에서 매일 확인하는 포트폴리오 모니터링 쿼리(세그먼트별
익스포저·연체율)와 Window Function 기반 Roll-rate(상태전이) 분석을 SQL로
직접 작성한 프로젝트입니다. 파이썬·머신러닝 중심이었던 기존 모듈들과 달리,
SQL 실무 역량 자체를 검증하는 데 목적을 두었습니다.

## 분석 배경 및 목적
리스크관리 실무에서는 모델링 이전 단계에서 SQL로 포트폴리오 현황을 상시
모니터링하는 작업이 일상적입니다. 본 분석은 대만 카드사 데이터를 소재로,
한도·연령 등 세그먼트별 익스포저 집중도를 확인하는 일반 집계 쿼리부터,
연체 상태가 시간에 따라 어떻게 전이되는지 추적하는 Window Function 기반
고급 쿼리까지 단계적으로 구현했습니다.

## 데이터
- 08-card-credit-risk와 동일한 대만 카드사 데이터(30,000명)를 SQLite
  `card_accounts` 테이블로 적재
- Roll-rate 분석을 위해 월별 연체상태(PAY_6~PAY_0)를 UNION ALL로 재구성한
  `pay_history_long`(고객×월 단위 롱포맷, 180,000행) 테이블을 추가 생성

## 방법론
1. **포트폴리오 세그먼트 집계**: CASE WHEN 기반 구간화(한도·연령·연체심각도)
   + GROUP BY로 세그먼트별 고객수·익스포저·부실률 산출
2. **Roll-rate 분석**: 6개월치 월별 연체상태를 세로로 재구성(UNION ALL) 후,
   `LAG() OVER (PARTITION BY ID ORDER BY month_seq)` 윈도우 함수로 고객별
   직전월 상태를 조회, 직전월→현재월 상태전이 매트릭스 산출

## 주요 결과

| 세그먼트 | 최저 부실률 | 최고 부실률 |
|---|---|---|
| 한도구간 | 11.21% (50만 이상) | 36.07% (5만 미만) |
| 연령대 | 20.25% (30대) | 28.32% (60대 이상) |

| 연체구간 | 익스포저 비중 | 다음달 부실전환율 |
|---|---|---|
| 정상(연체없음) | 82.39% | 13.83% |
| 1개월 연체 | 10.92% | 33.95% |
| 2개월 연체 | 5.92% | 69.14% |
| 3개월 이상 연체 | 0.77% | 71.92% |

**Roll-rate 매트릭스** (직전월 → 현재월 상태전이율)

| 직전월\현재월 | 정상 | 연체 |
|---|---|---|
| 정상 | 93.88% | 6.12% |
| 연체 | 23.78% | 76.22% |

## 시사점
- 한도구간·연령대 모두 리스크관리 직관과 일치하는 세그먼트 패턴을 보였으며,
  특히 한도가 낮을수록 부실률이 뚜렷이 높아지는 역상관 관계는 카드사의
  한도 심사 정책이 실제로 리스크를 반영하고 있음을 시사함
- 연체구간별 분석에서, 전체 익스포저의 17.61%(1개월 이상 연체)에 불과한
  고위험군이 다음달 33.95~71.92%라는 압도적으로 높은 부실전환율을 보여,
  소수의 연체 계좌에 리스크가 집중되어 있음을 정량적으로 확인함
- **Roll-rate 매트릭스가 이 프로젝트의 핵심 발견**: 연체 상태의 지속률
  (76.22%)이 회복률(23.78%)의 약 3.2배에 달해, 연체는 한 번 시작되면
  관성적으로 지속되는 경향이 강함을 실증함. 이는 카드사가 연체 발생 초기
  (1개월차)에 집중적으로 개입하는 실무 전략의 정량적 근거가 됨

## 한계점
- 카드 발급일자가 데이터에 없어 진정한 의미의 Vintage 분석(발급시점 코호트
  추적) 대신, 관측 시작월(6개월 전) 기준 연체상태로 코호트를 정의하는
  대안적 방식을 사용함
- Roll-rate 분석은 "정상/연체" 이진 상태로 단순화했으며, 연체 개월수별
  세분화된 상태전이(예: 1개월→2개월 연체 전이율)는 다루지 않음
- SQLite는 파일 기반 경량 DB로 실제 은행권에서 사용하는 대용량 RDBMS
  (Oracle, PostgreSQL 등)와 문법·성능 특성에 차이가 있을 수 있음
